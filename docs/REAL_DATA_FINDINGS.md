### 5e. Reading the flaws.cloud numbers

- This is **unsupervised**, and the 'normal' history already contains attackers and learners poking at the site, so 'unusual' means unusual relative to that history, not to a clean baseline.
- Real IPs are anonymized and the geo registry is off, so travel, country and ASN signals contribute nothing; the IP layer can only see shared-IP and many-IP patterns.
- The surge check is a sanity check on one event visible in raw counts. It is not a recall measurement, and one detected surge says little about the next attack.
- Rule hit counts are alerts, not confirmed attacks: many identities in this dataset are legitimate or are learners, so counts overstate malicious activity.

## 6. What real data taught

1. **Synthetic recall does not transfer.** The rules caught everything the generator produced and a minority of real techniques; the difference is the generator author's blind spots, which is why this check exists.
2. **Schema fidelity matters.** Two shipped rules were wrong on real record shapes. Real exports also contain top-level JSON arrays, missing fields, `AWSAccount` identities, IPv6 and empty source IPs, anonymized fake regions and leading-zero IPs; fuzz tests now cover these and the ingestor handles them.
3. **Alert floods.** Per-event rules flooded on real bursts (root usage on the SANS lab; instance launches on flaws.cloud). The engine now folds repeats per rule, identity and source IP within five minutes into one alert, and root usage is deduplicated per IP per hour.
3b. **AWS service principals look like attackers to naive rules.** On the SANS lab the AccessDenied-burst rule (R023) fired 164 times on `delivery.logs.amazonaws.com`, an AWS service delivering logs. Service principals are now excluded from that rule.
4. **Identity type is not a reliable human/service signal.** Many Stratus steps run as an assumed role, so rules that exclude `AssumedRole` to avoid service noise would miss an attacker holding stolen role credentials. That trade-off is deliberate and visible in R024 and R030.
5. **Duplicates are common in real exports** and must be dropped by `eventID`.
