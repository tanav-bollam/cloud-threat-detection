# Detections

> Generated by `scripts/make_results.py` from `rules/*.yaml`, `config/detector.yaml` and the feature definitions.

## Rules (Sigma-inspired YAML, evaluated per event; thresholds and sequences are windowed)

| ID | Severity | MITRE | Title | What it detects | Known false positives |
| :--- | :--- | :--- | :--- | :--- | :--- |
| R018 | HIGH | Initial Access / T1078.004 | Root account used | Any activity by the root principal. Root should only appear for break-glass tasks. | Documented break-glass procedures, billing changes. |
| R019 | MEDIUM | Initial Access / T1078.004 | Console login without MFA | A successful ConsoleLogin where MFA was not used. | Accounts exempt from MFA by policy (should be none). |
| R020 | MEDIUM | Credential Access / T1110 | Repeated failed console logins | Five or more failed ConsoleLogin events from one source IP within ten minutes (password guessing / spraying). | A user who forgot their password, usually 2-3 failures. NAT'd offices can aggregate several users. |
| R021 | HIGH | Credential Access / T1110 | Successful console login after repeated failures | A ConsoleLogin succeeded from an IP that had five or more recent failures, so the guessing worked. | A user who finally remembered the password; check the IP is a known one. |
| R022 | MEDIUM | Initial Access / T1078.004 | Offensive-tooling user agent | User agent matches Kali/Pacu/curl/python-requests, which legitimate AWS tooling does not use against AWS APIs. | Security team scripts; internal tooling written with requests/curl against signed APIs. |
| R023 | MEDIUM | Discovery / T1580 | Burst of AccessDenied errors (enumeration) | A principal produced 15+ authorization failures in ten minutes, the footprint of permission brute-forcing tools. | Misconfigured automation retrying a forbidden call; look at distinct event names. |
| R024 | HIGH | Exfiltration / T1530 | Mass S3 object download by a human user | An IAM user performed 250+ GetObject calls in ten minutes. Service roles are excluded because bulk reads are normal for them. | Data migrations or analysts exporting large datasets. |

| R007 | MEDIUM | Persistence / T1098.001 | Access key created for a different user | CreateAccessKey was called for a user other than the caller, a common way to mint durable credentials for a target identity. | Admins rotating keys for service accounts and onboarding new hires (both occur in normal operation). |

| :--- | :--- | :--- | :--- | :--- |
| IP001 | HIGH | Initial Access / T1078.004 | Impossible travel | The same identity appeared from two locations too far apart to travel between in the elapsed time. |
| IP002 | MEDIUM | Initial Access / T1078.004 | One IP new to many identities | An IP address that none of these identities had used before touched several identities (credential stuffing / pivoting). |
| IP003 | MEDIUM | Initial Access / T1078.004 | Identity active from many IPs | A single identity was used from an unusually large number of distinct IPs in a short period. |

## Behavioural anomaly layer (IsolationForest)

Identity × 15-minute windows sliding every 5 minutes. Features are computed against the identity's own baseline (known IPs, networks, countries, user agents, regions, active hours, typical volume). Trained on benign windows only; the alert threshold is calibrated on a benign validation week. Each flagged window carries SHAP reasons.

| Feature | Meaning |
| :--- | :--- |
| `log_n` | log(1 + events in the window) |
| `n_distinct_names` | distinct API names called |
| `n_services` | distinct AWS services touched |
| `read_ratio` | share of read-only calls |
| `err_ratio` | share of AccessDenied/Unauthorized errors |
| `high_risk_share` | share of high-risk APIs (IAM writes, logging/detection changes, sharing/permission changes, compute launch) |
| `recon_ratio` | share of List/Describe/Get management calls (enumeration signature) |
| `new_ip` | share of events from an IP never seen for this identity |
| `new_asn` | ... from a network (ASN) never seen |
| `new_country` | ... from a country never seen |
| `new_ua` | ... with a user agent never seen |
| `new_region` | ... in a region never used by the identity |
| `hour_rarity` | how unusual the hour of day is for this identity (1 = never active then) |
| `is_weekend` | window contains a weekend event |
| `log_max_dist` | log km between consecutive events' locations |
| `log_max_speed` | log implied travel speed (km/h) between consecutive events |
| `bytes_z` | S3 bytes read vs the identity's baseline (z-score) |
| `volume_z` | event count vs the identity's baseline (z-score) |
| `log_n_ips` | log distinct source IPs |
| `login_fail` | log failed console logins |
| `type_user` | identity is an IAM user |
| `type_role` | identity is an assumed role |
| `type_root` | identity is root |

High-risk API set used by `high_risk_share`: CreateUser, CreateAccessKey, DeleteAccessKey, AttachUserPolicy, PutUserPolicy, AttachRolePolicy, PutRolePolicy, CreateLoginProfile, UpdateAssumeRolePolicy, CreateRole, StopLogging, DeleteTrail, UpdateTrail, PutEventSelectors, DeleteDetector, UpdateDetector, DeleteFlowLogs, PutBucketPolicy, PutBucketAcl, ModifySnapshotAttribute, AuthorizeSecurityGroupIngress, CreateFunction20150331, RunInstances, RequestSpotInstances, DeleteBucket, TerminateInstances.

## Scoring and incidents

```yaml
scoring:
  severity_points:
    LOW: 15
    MEDIUM: 35
    HIGH: 60
    CRITICAL: 90
  weights:
    rule: 1.0
    anomaly: 1.0
    ip: 1.0
  anomaly:
    margin_low: 0.03
    margin_high: 0.08
    margin_full: 0.15
    max_points: 60
  corroboration_bonus: 12
  tactic_bonus: 8
  severity_from_risk:
    MEDIUM: 30
    HIGH: 55
    CRITICAL: 85
  escalate_min_tactics: 3
  anomaly_feature_tactics:
    new_country: Initial Access
    new_ip: Initial Access
    new_asn: Initial Access
    log_max_speed: Initial Access
    recon_ratio: Discovery
    err_ratio: Discovery
    n_distinct_names: Discovery
    high_risk_share: Persistence
    bytes_z: Exfiltration
    login_fail: Credential Access
incidents:
  gap_s: 3600
  high_severity_gap_s: 21600
```

Alerts get a 0-100 risk (rule severity points, anomaly margin over the threshold, or IP signal points). Alerts for the same identity or non-organisation IP within the gap join one incident; an identity tied to a HIGH+ alert stays linked for the longer gap. Incident severity is the max alert severity, escalated by tactic count and risk. The MITRE chain is ordered by *detection* time.
